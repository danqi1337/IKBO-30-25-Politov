# Эмулятор оболочки UNIX (вариант 21)

## 1. Общее описание

Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом
(tkinter). Реализован на Python 3.10+, внешних зависимостей нет.
Заголовок окна формируется из реальных данных ОС:
`Эмулятор - [username@hostname]`.

Состояние проекта: **этап 4 (основные команды)**.

## 2. Функции и настройки

### Виртуальная файловая система (VFS)

Источник VFS - каталог на диске (`--vfs PATH`). При запуске он целиком
читается в память (в виде дерева узлов), после чего диск не
используется: все операции выполняются только над деревом в памяти,
файлы на диске не распаковываются и не изменяются.

- Файлы `.gitkeep` и символьные ссылки при загрузке пропускаются
  (`.gitkeep` нужен, чтобы хранить пустые каталоги в git).
- Если `--vfs` не указан, создаётся небольшая VFS по умолчанию.
- Ошибки загрузки (каталог не найден, указан файл вместо каталога -
  «неверный формат») выводятся в окно, эмулятор продолжает работу с
  пустой VFS.
- Приглашение показывает текущий каталог VFS: `user@host:/путь$`.

Примеры VFS для проверок: `tests/vfs/minimal` (один файл),
`tests/vfs/files` (несколько файлов), `tests/vfs/deep` (вложенность
от трёх уровней, есть пустые каталоги).

### Парсер

Строка делится на слова по пробелам. Поддерживаются:

- двойные кавычки `"my dir"` (внутри работает `\"` и `\\`);
- одинарные кавычки `'a b'` (всё внутри сохраняется как есть);
- пустой аргумент `""`;
- экранирование `a\ b`.

Символ `#` в начале слова начинает комментарий до конца строки.
Ошибки разбора (незакрытая кавычка, `\` в конце строки) выводятся
как `parse error: ...`.

### Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | путь к каталогу на диске, из которого загружается VFS |
| `--log PATH` | путь к CSV-журналу (по умолчанию `emulator_log.csv`) |
| `--script PATH` | путь к стартовому скрипту |
| `--headless` | консольный режим без окна (для автотестов и скриптов ОС) |

При запуске все параметры выводятся в окно (консоль). Ошибки чтения
скрипта и открытия журнала выводятся туда же как `Ошибка: ...`,
эмулятор продолжает работу (без скрипта или без журнала).

### Журнал (CSV)

Каждый вызов команды (в том числе ошибочный и неизвестный) пишется
в файл журнала. Столбцы: `timestamp` (дата и время, ISO 8601), `user`
(имя пользователя ОС), `command`, `arguments` (JSON-список), `status`
(`ok` / `error`). Заголовок пишется в новый файл, затем события
дописываются.

### Стартовый скрипт

Файл с командами эмулятора, по одной в строке. Пустые строки и
комментарии (`# ...`) пропускаются. При выполнении на экране
показываются и ввод (с приглашением), и вывод, как в диалоге.
Строка с ошибкой пропускается с сообщением
`[скрипт] ошибка в строке N, строка пропущена`. `exit` в скрипте
завершает работу эмулятора.

### Команды

| Команда | Описание |
|---------|----------|
| `ls [-l] [-a] [путь...]` | содержимое каталога или имя файла |
| `cd [путь]` | смена каталога; без аргумента - корень VFS |
| `tail [-n N] файл...` | последние N (по умолчанию 10) строк файла |
| `tac файл...` | строки файлов в обратном порядке |
| `vfsinfo` | служебная: источник VFS, число каталогов, файлов и байт |
| `exit` | завершает работу эмулятора |

**ls**: `-l` - подробный список (тип `d`/`-`, владелец, размер, имя),
`-a` - показывать скрытые файлы (имена с `.`), флаги можно склеивать
(`-la`). Для нескольких путей перед списком печатается `путь:`.
Пути абсолютные и относительные, поддерживаются `.` и `..`.

**cd**: `cd ..`, `cd /a/b`, `cd` (в корень). Приглашение показывает
новый каталог.

**tail**: число строк задаётся `-n N`, `-nN` или `-N`; для
нескольких файлов выводятся заголовки `==> имя <==`. Чтение из stdin
не поддерживается.

**tac**: для нескольких файлов строки каждого выводятся в обратном
порядке по очереди.

Ошибки: `ls: cannot access 'x': No such file or directory`,
`cd: x: Not a directory`, `tail: missing file operand`,
`tail: invalid number of lines: 'x'`, `invalid option -- 'z'`,
`foo: command not found`, `cd: too many arguments`,
`exit: too many arguments`.

В окне работает история команд (стрелки вверх/вниз).

## 3. Сборка и тесты

Сборка не требуется. Нужны Python 3.10+ и tkinter
(в Debian/Ubuntu: `sudo apt install python3-tk`).

```sh
./run.sh --script tests/scripts/test_stage2.txt   # или make run ARGS=...
make test                                         # запуск тестов
```

В Windows вместо `run.sh` используйте `run.bat`.

Скрипты реальной ОС для проверки параметров (есть версии `.sh` и
`.bat`) лежат в `tests/os_scripts/`:

- `check_script_param` — параметр `--script`;
- `check_log_param` — параметр `--log`;
- `check_all_params` — все параметры вместе и `--help`.

Скрипты ОС для проверки VFS (`.sh` и `.bat`):

- `check_vfs_minimal`, `check_vfs_files`, `check_vfs_deep` - разные
  варианты VFS;
- `check_vfs_errors` - ошибки загрузки и VFS по умолчанию.

Запуск стартового скрипта этапа 4: `tests/os_scripts/run_stage4.sh`
(или `.bat`).

Стартовые скрипты эмулятора лежат в `tests/scripts/`:
`test_stage2.txt`, `test_stage3.txt` (все команды этапов 1-3, режимы и
ошибки), `test_stage4.txt` (ls, cd, tail, tac; запускать с
`--vfs tests/vfs/deep`), `vfs_info.txt`.

## 4. Примеры

```text
root@vm:/$ ls -l "my dir" 'a b' ""
ls: args=['-l', 'my dir', 'a b', '']
root@vm:/$ cd one two
cd: too many arguments
root@vm:/$ cd "unclosed
parse error: unterminated quote "
root@vm:/$ foo --bar
foo: command not found
```

Работа с VFS (`./run.sh --vfs tests/vfs/deep`):

```text
root@vm:/$ ls -l
d root  0 home
- root 56 readme.txt
d root  0 tmp
root@vm:/$ cd home/alex
root@vm:/home/alex$ tail -n 2 log.txt
строка журнала 11
строка журнала 12
root@vm:/home/alex$ tac notes.txt
позвонить маме
купить хлеб
Мои заметки
root@vm:/home/alex$ cd notes.txt
cd: notes.txt: Not a directory
```

Запуск со скриптом и журналом:

```sh
./run.sh --headless --log /tmp/log.csv --script tests/scripts/test_stage2.txt
```

```text
timestamp,user,command,arguments,status

2026-10-07T18:52:08,root,foo,"[""--bar""]",error
```
